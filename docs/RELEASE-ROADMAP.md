# BBK AUCTION — Release Roadmap

อัปเดต: 23 กันยายน 2026

เอกสารนี้บันทึกข้อกำหนดเพิ่มเติมจากพี่บอล และแยกสถานะจากสิ่งที่มีอยู่จริงในระบบ

## คำตัดสินที่อนุมัติแล้ว

- ใช้ Next.js + Vercel + Supabase ส่วนกลาง
- ระยะแรก BBK เป็นผู้ขายเพียงบัญชีเดียว
- ผู้ประมูลต้องยืนยันอีเมลและผ่านการอนุมัติจากแอดมิน
- เวลา ราคา bid ผู้ชนะ และการปิดประมูลยึดฐานข้อมูลเป็นหลัก
- ค่าธรรมเนียมผู้ซื้อ 10% และ VAT 7% ของค่าธรรมเนียม รวมผลต่อยอดชำระ 10.7%
- ขั้นเพิ่มราคาตามราคาปัจจุบัน: ต่ำกว่า 1,000 บาท +10 บาท, 1,000–4,999 บาท +50 บาท, ตั้งแต่ 5,000 บาท +100 บาท
- ผู้ชนะต้องชำระภายใน 24 ชั่วโมง; ไม่จ่ายครั้งแรกยกเลิกและเตือน ครั้งที่สองระงับรอแอดมินตรวจ
- ระบบเงินจริงยังปิดจนกว่าจะได้รับข้อมูลบัญชี/QR ร้านและกติกาค่าจัดส่ง
- เริ่มการแจ้งเตือนภายในเว็บไซต์ก่อน และเตรียมต่อ LINE/อีเมล/SMS ภายหลัง

## จุดที่ยังต้องตัดสินใจก่อนเปิดรับเงินจริง

1. บัญชีธนาคาร/PromptPay หรือภาพ QR ทางการของร้าน
2. ค่าส่ง การคืนสินค้า และช่วงเวลายื่นข้อโต้แย้ง
3. ข้อความเตือนและระยะเวลารอแอดมินตรวจเมื่อผิดนัดครั้งที่สอง

## สถานะ P0

| งาน | สถานะ | หมายเหตุ |
|---|---|---|
| เปิด → bid → ปิด → คำนวณผู้ชนะ | มีแล้ว | เปิด/ปิดตามเวลาฐานข้อมูล สร้างผลและ Order เพียงครั้งเดียว |
| ราคาแบบ Realtime | มีพื้นฐานแล้ว | โหลดซ้ำจากฐานข้อมูลเมื่อเชื่อมต่อใหม่ |
| ค่าธรรมเนียมและยอดชำระรวม | มีแล้ว | 10% + VAT 7% ของค่าธรรมเนียม; 1,000 → 1,107 บาท ไม่รวมค่าส่ง |
| ป้องกัน bid ต่ำ | มีแล้ว | ตรวจใน `place_bid` RPC |
| ราคาขั้นต่ำในการเพิ่ม | มีแล้ว | ฐานข้อมูลบังคับช่วง +10/+50/+100 บาท |
| ป้องกัน bid ซ้ำ | มีแล้ว | ใช้ idempotency key ต่อผู้ประมูล |
| ป้องกันคำสั่งซื้อซ้ำ | มีแล้ว | หนึ่ง Auction สร้างได้หนึ่ง Order และการปิดซ้ำคืนผลเดิม |
| ประวัติผู้เสนอราคา | มีแล้ว | หน้า `/account` แสดง bid รายการชนะ และการแจ้งเตือน |
| มือถือ | มี responsive พื้นฐาน | ต้องทดสอบทุก flow บนอุปกรณ์จริง |
| หลังบ้านรายการ | มีแล้ว | สร้าง แก้ ส่งตรวจ อนุมัติ เปิด/ปิดอัตโนมัติ |
| ผู้ขายเฉพาะ BBK | มีแล้ว | มีกฎฐานข้อมูลป้องกันผู้ขายรายที่สอง |

## งานชุดถัดไป

1. รับข้อมูลบัญชี/QR ร้านและกำหนดค่าส่ง
2. ทำการแนบสลิปใน Storage แบบ private โดยยังให้แอดมินตรวจเอง
3. ทำคิวแอดมินตรวจเงินและสถานะ `รอชำระ → ตรวจสอบแล้ว → จัดส่งแล้ว → สำเร็จ/ยกเลิก`
4. เพิ่มงานหมดเวลาชำระ การเตือนครั้งแรก และระงับครั้งที่สองแบบมี Audit log
5. ทดสอบ bid พร้อมกัน คำขอซ้ำ เวลาปิด และการสร้าง Order ซ้ำ
6. ทดสอบมือถือและทดลองกับลูกค้า 10–20 คน

## ขอบเขตที่ยังไม่เปิด

- ยังไม่ส่งข้อความจริงผ่าน LINE อีเมล หรือ SMS
- ยังไม่รับผู้ขายภายนอก
- ยังไม่เปิด payment gateway หรือเคลื่อนเงินจริงอัตโนมัติ
- ยังไม่เปิด refund/payout อัตโนมัติ

## เกณฑ์พร้อมทดลอง

- ประมูลหนึ่งรายการตั้งแต่เปิดจนแอดมินยืนยันชำระและใส่เลขพัสดุได้
- ยอดค่าธรรมเนียมและยอดรวมตรงตามอัตราที่อนุมัติทุกกรณี
- bid พร้อมกันและคำขอซ้ำไม่สร้างผู้ชนะหรือ Order ซ้ำ
- ลูกค้าเห็นประวัติ bid รายการชนะ ยอดชำระ และสถานะล่าสุด
- แอดมินเห็น Audit trail ของราคา ผลประมูล การชำระ และการจัดส่ง
- หน้าใช้งานหลักผ่านการทดสอบบนมือถือ
