# BBK AUCTION — ผลทดสอบก่อนแยกแอป

วันที่ทดสอบ: 24 กันยายน 2026  
ฐานข้อมูล: Supabase โปรเจกต์ `bbk-auction`  
วิธีทดสอบ: SQL Editor โดยใช้ฟังก์ชันชั่วคราวและ rollback สำหรับคำสั่งที่สร้างหรือแก้ข้อมูลทดสอบ

## ผ่าน

| รายการ | ผล |
|---|---|
| รับคำขอเสนอราคาครั้งแรก | ผ่าน — `BID_ACCEPTED`, `idempotent=false` |
| ส่งคำขอเดิมซ้ำ | ผ่าน — คืนผลเดิม `BID_ACCEPTED`, `idempotent=true` |
| หนึ่ง request key สร้างหนึ่ง bid | ผ่าน — พบ 1 รายการ |
| ใช้ request key เดิมกับราคาใหม่ | ผ่าน — ปฏิเสธด้วย `IDEMPOTENCY_KEY_REUSED` |
| เสนอราคาต่ำกว่าขั้นต่ำล่าสุด | ผ่าน — ปฏิเสธด้วย `BID_BELOW_MINIMUM` |
| ปิดประมูลรายการเดิมซ้ำ | ผ่าน — คืนผลเดิม `SAME_RESULT` |
| หนึ่งการประมูลมีผลประมูลเดียว | ผ่าน — พบ 1 รายการ |
| หนึ่งการประมูลมีออเดอร์เดียว | ผ่าน — พบ 1 รายการ |

ชุดคำสั่งที่ใช้ทดสอบอยู่ที่
`supabase/tests/manual/20260924_verify_bid_idempotency_and_finalization_rollback.sql`

## ยังไม่ได้ทดสอบ

- คำขอจากผู้ประมูลหลายบัญชีที่เข้ามาพร้อมกันจริงจากคนละการเชื่อมต่อ
- bid ที่เข้าก่อน ตรง และหลังเส้นตายด้วยโหลดพร้อมกัน
- การหลุดและเชื่อม Realtime ใหม่ระหว่างมี bid
- การกู้คืนฐานข้อมูลจาก backup

ผลชุดนี้ยืนยัน idempotency และข้อจำกัดสำคัญในฐานข้อมูล แต่ยังไม่ใช่หลักฐานว่าระบบพร้อมเปิด production จนกว่าการทดสอบหลายการเชื่อมต่อและการกู้คืนจะผ่าน
