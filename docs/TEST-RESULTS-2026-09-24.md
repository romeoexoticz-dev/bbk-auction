## ข้อค้นพบและสถานะการแก้ไข

- ติดตั้ง migration `202609240024_product_trust_fields.sql` แล้วในวันที่ 24 กันยายน 2026 และตรวจพบคอลัมน์ความน่าเชื่อถือสินค้า 5 คอลัมน์, ฟังก์ชันสร้าง/แก้ไข 2 ฟังก์ชัน, trigger ก่อนเผยแพร่ 1 ตัว และ unique index รูปหน้า/หลัง 2 ตัว
- แก้รูปแบบ constraint ของ `auction_media.media_kind` ให้ใช้ `= ANY(array)` ตามรูปแบบที่ฐานข้อมูลรองรับ
- ปิดสิทธิ์ `anon` ของฟังก์ชันสร้างและแก้ไขรายการโดยตรงแล้ว; `authenticated` ยังเรียกใช้ได้ตามที่ออกแบบ
- การปฏิเสธ bid หลังเส้นตายที่เห็นเป็น `AUCTION_NOT_LIVE` เพราะงานปิดอัตโนมัติเปลี่ยนสถานะเป็น `ended` ก่อนคำขอเข้าถึงฟังก์ชัน ไม่ใช่ข้อผิดพลาดของการตรวจขั้นต่ำราคา
- ฟอร์มรูป 3–5 รูปเกินค่าเริ่มต้น 1 MB ของ Next.js Server Actions จึงเพิ่ม `experimental.serverActions.bodySizeLimit` เป็น 60 MB ให้สอดคล้องกับข้อจำกัดรูปละ 10 MB ของฟอร์ม
- พบว่านโยบายอัปโหลด `payment-evidence` อ่าน `marketplace_settings` โดยตรง และ PostgreSQL สามารถประเมินนโยบาย INSERT นี้ขณะอัปโหลดไป bucket อื่นได้ จึงทำให้ `auction-media` ถูกปฏิเสธด้วย `permission denied for table marketplace_settings`
- ติดตั้ง migration `202609240027_storage_payment_policy_isolation.sql` แล้ว โดยย้ายการตรวจสิทธิ์ชำระเงินเข้า security-definer function และใช้ `CASE` แยก bucket; ตารางตั้งค่าร้านยังเป็นข้อมูลปิด
- เพิ่ม server log แบบไม่บันทึก path หรือข้อมูลลูกค้า เพื่อให้หาสาเหตุการอัปโหลดรูปและ metadata ล้มเหลวได้เร็วขึ้น
- พบ deadlock เมื่อผู้ประมูลต่างบัญชีเพิ่ม `bid_attempts` แล้วพยายามล็อก auction เดียวกันด้วย `FOR UPDATE`; Foreign Key ถือ `KEY SHARE` คนละ transaction ทำให้ล็อกไขว้กัน
- ติดตั้ง migration `202609240028_fix_concurrent_bid_deadlock.sql` แล้ว โดยใช้ `FOR NO KEY UPDATE` เพื่อยัง serialize ราคาต่อ auction แต่ไม่ชนกับ Foreign Key `KEY SHARE`; ทดสอบซ้ำจาก 2 การเชื่อมต่อแล้วผ่าน
- ติดตั้ง migration `202609250029_automatic_bid_extension.sql` แล้วในวันที่ 25 กันยายน 2026: รายการใหม่และรายการที่ยังไม่ Live ใช้กติกา 2 นาที + 2 นาที ส่วนรายการที่ Live อยู่ไม่ถูกเปลี่ยนกติกากลางคัน

## ยังไม่ได้ทดสอบ

- bid ที่เข้าตรงเส้นตายแบบโหลดจำนวนมาก (ชุดนี้ยืนยันเฉพาะหลังเส้นตายและ 2 การเชื่อมต่อ)
- การกู้คืนฐานข้อมูลจาก backup

ผลชุดนี้ยืนยัน idempotency, การแย่งเสนอราคาจากสองการเชื่อมต่อหลังแก้ deadlock, Realtime และการกลับเข้าหลังหลุด, การปิดอัตโนมัติ, การปิดพร้อมกัน, วงจรฉบับร่างถึงตั้งเวลา, การอัปโหลดรูปจริง และการติดตั้ง migration `024`/`027`/`028` ได้ แต่ยังไม่ใช่หลักฐานว่าระบบพร้อมเปิด production จนกว่าการทดสอบโหลดและการกู้คืนฐานข้อมูลจะผ่าน
